# 运维容量与可观测性

系统容量规划以 Cloudflare Workers 与 D1 免费额度为基线设计，运行指标依托 Cloudflare 控制台与分析平台，避免将监控数据写回 D1 造成额外配额开销。存储结构与生命周期见 [database.md](database.md)。

## 1. 资源预算基线

| 资源项 | Cloudflare Workers Free 基准 |
| --- | --- |
| 静态资产请求 | 免费承载，不计入 Worker 请求次数 |
| Worker 请求总数 | 100,000 次/天 |
| Worker CPU 耗时 | 10 ms/次 |
| D1 行读取额度 | 5,000,000 行/天 |
| D1 行写入额度 | 100,000 行/天 |
| D1 存储上限 | 5 GB/账户（单库 500 MB） |
| Cron Triggers | 5 个/账户 |

Downloads Worker 静态资产独立分发，安装脚本与二进制请求由边缘 CDN 响应，不占用 Worker 调用与 CPU 额度。

## 2. 请求与写入开销模型

### 2.1 请求预算评估

Agent 默认每 300 秒发起一次心跳，并与流量结算合并提交：

- 单节点请求量：`86400 / 300 = 288` 次/天。
- 100 节点规模下的日常请求约 28,800 次/天，占免费调用额度约 29%，剩余额度支持用户订阅与日常管理访问。
- 定时任务（`*/15` 与每日一次）每天调用约 97 次，开销可忽略。

### 2.2 D1 写入容量测算

默认流量结算间隔为 900 秒（每天 96 批次）：

| 场景规模 | 心跳写入 | 报表记录 | 节点桶 | 站点桶 | 用户桶 | 周期汇总 | 每日写入合计 | 免费额度占比 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 20 节点 / 50 组合 / 50 用户 | 5,760 | 1,920 | 1,920 | 96 | 4,800 | 4,800 | 19,296 | 19.3% |
| 100 节点 / 100 组合 / 50 用户 | 28,800 | 9,600 | 9,600 | 96 | 9,600 | 4,800 | 62,496 | 62.5% |

运行约束与调优方向：
- 默认 900 秒流量结算间隔是保持在写入预算内的关键参数。
- 报表凭证、小时桶与周期汇总在同一批次事务中提交，保证写入效率与数据一致。
- 周期扫描任务仅为发生周期推进或状态变化的用户执行写入，稳态运行下写入行数接近为零。
- 可通过运行 `npm run capacity` 在本地环境验证不同规模下的数据行数与日写入开销。

## 3. CPU 耗时控制

- 耗时控制点：主要消耗集中在 Clash YAML 序列化、URL 编码计算及 Access JWT 签名比对；数据库 I/O 等待不占用 CPU 时间。
- 目标指标：控制面管理端点与订阅端点在 p95 分位下的 CPU 执行时间维持在 5 ms 以内。
- 压测评估：使用 `npm run capacity` 进行 100 节点、500 条分流规则规模的基准测试，保持至少 50% 的 CPU 裕量。

## 4. 可观测性与告警指标

### 4.1 日志规范与敏感信息规避

- 服务端统一日志字段包含 `request_id`、匹配路由、HTTP 状态码、业务错误码、处理耗时以及 D1 实际读写行数。
- 客户端日志记录 `report_id`、节点标识、配置版本、凭证版本及重试计数。
- 日志输出严格过滤 Token、订阅链接、用户 UUID 及原始请求报文体。

### 4.2 核心告警监控项

- 资源水位告警：Worker 每日请求数、CPU 耗时或 D1 日写入量接近免费配额上限（达到 80% 阈值）。
- 节点可用性告警：连续 3 个心跳周期未收到节点上报。
- 配置自愈告警：节点连续报告配置语法测试未通过或回滚事件。
- 任务执行告警：定时周期任务执行抛出异常。

## 5. 故障行为矩阵

| 故障场景 | 系统自愈与响应行为 |
| --- | --- |
| D1 或 Worker 暂时不可用 | Agent 本地保留待发送报表并执行指数退避重试；订阅端点返回 503；管理端提示网络重试 |
| Worker 免费调用额度耗尽 | 边缘返回 429 或 1027；Agent 遵守 Retry-After 退避，本地数据持久化保存 |
| 单个节点失去网络连接 | 现有代理连接保持工作；超出 3 个心跳周期后控制面将其标记为离线并从新订阅中剔除 |
| Xray StatsService 异常 | 节点标记为 `degraded` 但保留订阅分发；流量报表标记 `has_counter_gap` |
| Xray 进程异常重启（计数器归零） | Agent 识别计数器回退，按当前采样值结算并标记数据断层，避免负增量入账 |
| 远程配置语法校验未通过 | Agent 保持原配置运行，向控制面上报结构化校验错误，避免服务中断 |
| 远程配置重启后健康检查失败 | Agent 自动将备份旧配置原子回滚并重启，向控制面上报失败状态 |
| Agent 状态数据丢失 | 重新连接控制面拉取最新期望凭据与配置；未确认流量由断层补偿机制平滑过渡 |
