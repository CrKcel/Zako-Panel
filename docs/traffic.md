# 流量采集、入账与月度配额

这套流量系统的核心思路是：**Agent 在节点本地算好增量并按小时切分，控制面收到后幂等写入几张聚合表**。这样既不怕网络重传导致重复扣费，也能让面板图表和订阅校验几乎瞬间出结果。

接口字段见 [api.md](api.md)，表结构见 [database.md](database.md)，Agent 进程配置见 [agent.md](agent.md)。

---

## 1. Agent 怎么从 Xray 拿流量

Agent 通过本机环回 gRPC（默认 `127.0.0.1:10085`）调用 Xray 的 `StatsService`：

- **只采业务入站**：只统计代理入站（如 `vless-reality`）和 Level 0 用户的 `uplink` / `downlink`，排除本机 gRPC 管理端口自身的流量。
- **用户怎么对应**：每个订阅用户都有一个全局唯一的 `email`（形如 `u_<ULID>`，对应数据库 `subscribers.xray_email`），Xray 按这个 `email` 记账。
- **只读不清空**：Agent 查询时传 `reset=false`，自己维护上一次的读数基线，防止多方读取或崩溃时把计数器弄丢。

---

## 2. 本地采样与按小时拆包

Agent 内部有两个独立循环在跑：**每 30 秒采样一次**、**每 15 分钟上报一次**。

### 2.1 采样与防负数（Xray 重启怎么办）

每次采样时，Agent 把最新读数和 BoltDB 里存的“上一次基线”做对比：

- **正常情况**（新读数 ≥ 基线）：增量 = `新读数 - 基线`，然后把基线更新为新读数。
- **Xray 重启了**（新读数 < 基线，或检测到 Xray 运行时间回退）：说明 Xray 计数器刚清零过。Agent 直接把**当前新读数**当成这段时间的增量，并打上 `has_counter_gap` 标记，防止算出负数流量。

每次采样计算出的增量、最新基线和状态，都在同一个 BoltDB 事务里落盘，节点断电重启也不会丢数据。

### 2.2 为什么上报要按“自然小时”拆分

控制面是按整点小时桶（如 `14:00~15:00`、`15:00~16:00`）存流量的，因此要求**单份报表不能跨小时**，且最多带 **40 个用户条目**。

举个例子：

> 假设上次上报在 `14:50`，这次到了 `15:05` 触发上报。  
> Agent 会自动把 `14:50~15:00` 和 `15:00~15:05` 拆成**两份独立的报表**（各有自己的 `report_id`），分别入 `14:00` 和 `15:00` 的小时桶。如果某个小时里活跃用户超过 40 个，也会自动拆成多份。

此外：
- 报表会持久化进本地待发送队列，只有收到控制面确认后才删除；
- 如果节点断网超过 7 天，太老的报表会被本地主动丢弃，避免积压。

## 3. Worker 怎么幂等入账

控制面收到 `POST /api/v1/agent/report` 后，按以下顺序处理：

1. **校验身份与时间**：验证 Agent Bearer Token，检查报表时间范围是否合法、是否落在同一个自然小时内（未来时钟偏移容忍 5 分钟以内）。
2. **先记心跳**：把节点的最后活跃时间、健康状态、版本和系统负载写入 `nodes` 表。**心跳和流量是解耦的**——就算后面的流量数据冲突了，心跳依然会正常更新。
3. **映射用户**：把报表里的 `xray_email` 批量查出对应的 `subscriber_id`。万一遇到已经解绑或面板不认识的 `email`，流量依然记入节点和全站总账，不丢数据。
4. **原子写入多张表**：在同一个 D1 事务批处理里完成：
   - 往 `traffic_reports` 插一条收据（主键 `(node_id, report_id)`）；
   - 累加 `node_traffic_hourly`（节点小时桶）、`site_traffic_hourly`（全站小时桶）、`user_traffic_hourly`（用户-节点小时桶）；
   - 累加 `subscriber_usage`（用户当月总用量）。
5. **防重与冲突处理**：
   - 如果 `report_id` 已经存在，比对这次请求的规范化 JSON SHA-256 哈希；
   - **哈希一致**：说明是网络超时重试，直接返回成功（`ack_report_id`），不再重复加流量；
   - **哈希不一致**：说明有人用同一个 `report_id` 塞了不同数据，返回 `409 REPORT_CONFLICT`。

## 4. 月度周期与超额怎么判

### 4.1 自然月重置

- 用户的流量周期按 **UTC 自然月**算（每月 1 日 00:00 UTC 到次月 1 日 00:00 UTC）。
- Worker 每 15 分钟跑一次定时任务（Cron `*/15 * * * *`）：扫描到期的周期，把 `subscriber_usage` 累计清零并把周期推到下个月。

### 4.2 用户状态怎么派生

用户最终的 `subscribers.status` 按下面优先级判定（数字越小越优先）：

| 优先级 | 状态 | 什么时候变成这个状态 | 对代理的影响 |
| --- | --- | --- | --- |
| 1 | `disabled` | 管理员手动停用 | 禁止拉订阅，并从所有节点 Xray 移除凭据 |
| 2 | `expired` | 超过了有效期 | 同上 |
| 3 | `limited` | 设了流量上限，且当月用量 ≥ 上限 | 同上 |
| 4 | `active` | 没停用、没过期、没超额 | 正常下发订阅和节点权限 |

当定时任务或管理员操作导致用户状态变化时，面板会递增全局版本号 `meta.users_ver`。Agent 下次心跳拿到新版本号后，就会把失效用户从 Xray 里热移除——**正在跑的连接不断，新连接连不上**。
